Lesson 001 · Object Storage

Alternatif Penyimpanan selain Supabase untuk SIMTAS

Terkait misi: memilih penyimpanan produksi yang tepat untuk kampus.

Kenapa ini penting bagi project kamu

SIMTAS menyimpan dokumen skripsi (PDF) dan arsip. Rencana di Job 21 adalah Supabase Storage. Ada kabar baik yang membuat pilihanmu tidak mengunci (tidak vendor-lock):

Codebase SIMTAS sudah mengabstraksi storage di balik interface StorageService di backend/internal/domain/service/storage_service.go. Implementasinya dipilih lewat variabel STORAGE_PROVIDER di router.go (saat ini: local untuk stub, atau supabase). Artinya: untuk memakai penyimpanan lain, kamu cukup menulis satu implementasi baru dari interface itu — bukan menulis ulang logika upload/download.

Konsep kunci: standar S3 API

Hampir semua penyedia object storage berbicara dengan S3 API — kumpulan operasi HTTP standar (put objek, get, delete, presigned URL). Karena Supabase Storage sendiri memakai standar ini, dan semua alternatif di bawah ini juga S3-compatible, maka swap antar penyedia menjadi murah.

Pertanyaan sebenarnya bukan "mana yang paling mudah diganti", melainkan mana yang paling cocok untuk produksi kampus — urusan kendali data, biaya, kapasitas, dan operasional.

Sumber harga resmi: Cloudflare R2, Backblaze B2, AWS S3, MinIO.

Rekomendasi untuk misi kampus

  1. MinIO (self-hosted) — paling cocok bila kampus ingin data skripsi (termasuk privasi mahasiswa) sepenuhnya di bawah kendalinya. S3-compatible, gratis (Community/AGPL), dan SDK Go-nya (minio-go) enak dipakai di backend SIMTAS yang sudah Go.
  2. Cloudflare R2 atau Backblaze B2 — bila ingin managed tapi biaya unduh (egress) tidak bikin jebol. R2 bahkan egress-nya gratis.
  3. AWS S3 — aman & standar, tapi perhatikan biaya transfer keluar. Umumnya berlebihan untuk skala sebuah fakultas.
  4. Supabase Storage (rencana sekarang) — tetap oke, terutama jika kamu memang memakai Supabase untuk hal lain (auth/DB). Tapi ia mengikat ke ekosistem Supabase.
Catatan penting: anggap "kendali data" sebagai prioritas. Untuk dokumen skripsi (karya ilmiah berisi data pribadi), banyak kampus lebih suka data tinggal di server sendiri — itulah justifikasi utama MinIO self-hosted.
